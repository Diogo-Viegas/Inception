Inception

A complete web mini-infrastructure built from scratch with Docker and Docker Compose: an NGINX server, a WordPress instance, and a MariaDB database, each in its own container.

DockerDocker ComposeNGINXWordPressPHP-FPMMariaDBTLS

What is the project?

Inception asks you to set up a small infrastructure inside a virtual machine using Docker. Instead of downloading ready-made images, each service is built from a hand-written Dockerfile, starting from a Debian or Alpine base image.

Objective

Understand how the services of a web application communicate with each other and how to isolate, configure, and orchestrate them.

Tools

Dockerfiles, docker-compose.yml, Makefile, .env file, and secrets for credentials.

Result

A WordPress site accessible only via HTTPS on port 443, with data that persists even after deleting the containers.

Architecture

The only entry point is NGINX on port 443. The rest of the infrastructure lives in a private Docker network.

Both data services store everything on the host at /home/login/data. Container-to-container communication takes place on a dedicated Docker network, without --link or network: host.

The Services

1

NGINX

The entry point of the infrastructure. Accepts only TLSv1.2 or TLSv1.3 connections on port 443 and forwards PHP requests to WordPress via FastCGI.

2

WordPress + PHP-FPM

The application itself, installed and configured via script using WP-CLI. Runs without NGINX: PHP-FPM listens on port 9000 and receives requests from the proxy.

3

MariaDB

Stores WordPress content, users, and settings. Accessible only from the internal network, never from the outside.

Important Concepts

Docker vs. Virtual Machine

A container shares the host kernel and isolates only processes and the file system. It is much lighter than a VM, which brings a full operating system.

Docker Compose

Describes all services, networks, and volumes in a single file and spins everything up with a single command, reproducibly.

Volumes and Persistence

A container's file system is ephemeral. Volumes store data outside of it, on the host.

Docker Network

Containers resolve each other by service name (mariadb, wordpress) thanks to the internal DNS created by Compose.

Secrets and Environment Variables

No passwords appear in the Dockerfiles. Credentials come from .env files and Docker secrets, outside the repository.

PID 1

The main process of each container runs in the foreground as PID 1. Tricks like tail -f or sleep infinity are not accepted.

Rules Defining the Project

  • Each service has its own container and its own Dockerfile.
  • Base images: penultimate stable version of Debian or Alpine. No latest tags.
  • No ready-made images from Docker Hub are used (except the base image).
  • Containers restart automatically in case of failure.
  • The WordPress database has two users, one of them an administrator without "admin" in the name.
  • The domain login.42.fr points to the machine's local IP.

What You Learn

More than just memorizing commands, Inception forces you to think like a system administrator: isolate responsibilities, automate installation, protect credentials, ensure persistence, and understand the path of a request from the browser to the database.
